## Motivo de cada escolha

- **Session Manager:** nenhuma porta fica aberta e não há chaves para gerenciar. O agente usa conexão de saída HTTPS.
- **IP público:** o agente SSM precisa chegar à internet. VPC endpoints evitariam isso, mas custam cerca de US$ 7 por mês cada.
- **Modo `standard`:** a família t4g vem em `unlimited` por padrão, que pode cobrar CPU extra sem você perceber. Em `standard`, a instância só fica mais lenta quando os créditos acabam.
- **Arm:** binários feitos só para x86 não rodam. A t3.micro é a alternativa x86, também no Free Tier.

O comando exige o [Session Manager plugin](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html). Também dá para entrar pelo console: EC2 → mdraws1 → Connect → Session Manager.

### SSH via Session Manager (sem porta 22)

- Chave dedicada: `~/.ssh/mdraws1` (ed25519), autorizada no `ec2-user` via SSM Run Command.
- Session Manager plugin instalado localmente em `/usr/local/bin`.
- Teste OK (2026-10-26):

```bash
ssh -i ~/.ssh/mdraws1 -o IdentitiesOnly=yes \
  -o ProxyCommand="aws ssm start-session --target %h --document-name AWS-StartSSHSession --parameters portNumber=%p --profile aws-agent --region us-east-2" \
  ec2-user@i-021827cbe856e34b8
```

Atalho configurado em `~/.ssh/config` (backup em `~/.ssh/config.bak-mdraws1`): basta `ssh mdraws1`.
