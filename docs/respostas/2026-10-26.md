**1. Evite repetir profile e região.** Rode isto uma vez por terminal:

```bash
export AWS_PROFILE=aws-agent AWS_REGION=us-east-2
```

**2. Ver tudo de uma instância.** O comando abaixo devolve o JSON completo. Ele é bem longo, então use `less` para navegar:
```bash
aws ec2 describe-instances --instance-ids i-021827cbe856e34b8 | less
```

**3. Ver só os campos que interessam**, com `--query` e `--output table`. Foi assim que gerei a tabela acima:
```bash
aws ec2 describe-instances --filters Name=tag:Name,Values=mdraws1 \
  --query 'Reservations[].Instances[].{ID:InstanceId,Estado:State.Name,Tipo:InstanceType,IP:PublicIpAddress}' \
  --output table
```
- O `--filters` busca pelo nome em vez do ID. Também funciona com `Name=instance-state-name,Values=running`, entre outros.
- O `--query` usa a sintaxe JMESPath, que roda no seu computador e só recorta a resposta.
- O `--output` aceita `table`, `text` (bom para scripts) e `json`.

**4. Listar todas as instâncias do projeto:**
```bash
aws ec2 describe-instances \
  --query 'Reservations[].Instances[].[Tags[?Key==`Name`]|[0].Value,InstanceId,State.Name,InstanceType,PublicIpAddress]' \
  --output table
```

**5. Outras consultas úteis:**

| O que | Comando |
|---|---|
| Saúde (status checks) | `aws ec2 describe-instance-status --instance-ids <id>` |
| Só o IP público | `aws ec2 describe-instances --instance-ids <id> --query 'Reservations[0].Instances[0].PublicIpAddress' --output text` |
| Discos (EBS) | `aws ec2 describe-volumes --filters Name=attachment.instance-id,Values=<id>` |
| Security groups | `aws ec2 describe-security-groups --group-ids sg-063a3c05720c98302` |
| Log de boot (console) | `aws ec2 get-console-output --instance-id <id> --latest --output text` |
| Status no SSM | `aws ssm describe-instance-information --filters Key=InstanceIds,Values=<id>` |
| CPU da última hora | `aws cloudwatch get-metric-statistics --namespace AWS/EC2 --metric-name CPUUtilization --dimensions Name=InstanceId,Value=<id> --start-time $(date -u -d '-1 hour' +%FT%TZ) --end-time $(date -u +%FT%TZ) --period 300 --statistics Average --output table` |

**Se você usa o modo `standard` de créditos de CPU**, como na mdraws1, vale acompanhar o saldo de créditos. Quando ele chega a zero, a instância fica limitada a 20% da CPU, então um saldo baixo explica lentidão:

```bash
  --dimensions Name=InstanceId,Value=i-021827cbe856e34b8 \
  --start-time $(date -u -d '-1 hour' +%FT%TZ) --end-time $(date -u +%FT%TZ) \

```
